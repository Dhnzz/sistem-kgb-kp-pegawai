## 1. Overview
Web app internal (VPS kantor) untuk **mencatat & mengingatkan Kenaikan Gaji Berkala (KGB) tiap 2 tahun tepat dan Kenaikan Pangkat (KP) — struktural tiap 4 tahun tepat, fungsional berbasis kredit tahunan (12.5 / 25 per 1 Januari) dengan threshold per pangkat** — bagi ±100 pegawai. Sistem menghitung `nextDue` otomatis, menampilkan dashboard "siapa 60 hari lagi", mengirim **email + webhook H-60** (plus rekap admin), menambah kredit tiap 1 Januari dan auto-promote jika kredit ≥ threshold (reset 0), serta mencatat riwayat. Import Excel + template + seeder disediakan; v1 fokus pengingat & pencatatan (bukan cetak SK / SIASN).

Untuk siapa: **Admin Kepegawaian** (kelola & terima rekap) dan **Pegawai** (terima pengingat & lihat jadwal sendiri). Kenapa sekarang: pantauan manual via Excel rawan terlewat, telat berkas, data tercecer — sistem jadi single source of truth.

## 2. Goals & Non-Goals
**Goals**
- G1: 0 terlewat — 100% reminder H-60 terkirim (termasuk forecast kredit fungsional).
- G2: Visibility 10 detik — admin tahu siapa KGB/KP bulan ini & 60 hari ke depan via dashboard.
- G3: Single source of truth — TMT, pangkat, kredit, riwayat terpusat menggantikan Excel.

**Non-Goals**
- NG1: Bukan payroll (tidak hitung nominal gaji).
- NG2: Bukan SIASN/BKN sync (v1).
- NG3: Bukan approval berjenjang (v1 cukup admin/pegawai).
- NG4: Bukan mobile native.
- NG5: Bukan cetak SK di v1 — template cetak di v2.

## 3. MVP Scope
**MVP (v1 — wajib usable):**
- M1: CRUD pegawai + master pangkat (threshold_next per jenjang) + import Excel (template + preview validasi) + seeder 100 dummy + export rekap.
- M2: Engine jadwal — KGB +2y, KP struktural +4y, KP fungsional forecast kredit 1 Jan vs threshold → `nextDue` & `dueIn60`.
- M3: Dashboard — KPI cards + DueTable (tabs KGB/KP) + 2 chart (KGB per bulan Bar, KP by jenis Donut) + filter/search.
- M4: Cron harian 07:00 WIB — email H-60 ke pegawai + rekap admin + webhook POST HMAC + `notification_log` idempoten + retry 1x.
- M5: Riwayat kenaikan (`promotion_history`) + flow konfirmasi manual "Konfirmasi Naik" + auto-promote 1 Jan.
- M6: Auth NextAuth (admin/pegawai/viewer) + RBAC.

**Deferred (v2+):**
- WhatsApp reminder (via gateway, pakai webhook yang sudah ada).
- Template administrasi cetak (tinggal cetak).
- Notifikasi berjenjang H-30 & H-7 (di atas H-60).
- Approval workflow & e-sign, SIASN sync.

## 4. Architecture (summary)
**Stack:** Next.js 14+ (App Router, TS) monolith + Tailwind/shadcn + NextAuth + Prisma + PostgreSQL 16 + Nodemailer (SMTP configurable) + `fetch` webhook HMAC + `exceljs` + Docker Compose (app+postgres+nginx) di VPS kantor. Cron via `systemd timer → /api/cron/daily|yearly` (idempoten). Full detail di [[ARCHITECTURE]].

**Data flow ringkas:** Admin CRUD → Server Action → Prisma → Postgres → revalidate; Dashboard SSR hitung `nextDue` via `lib/schedule`+`credit`; Cron harian query `dueIn60` (incl. forecast) → `sendNotification` (email+webhook) → `notification_log` unique; Cron tahunan 1 Jan `kredit+=rate` → cek threshold → promote (reset 0) → history + email.

## 5. Design (summary)
**Flow:** Admin Login → Dashboard KPI → DueTable/Chart → Pegawai CRUD/Import → Rekap/Export → Riwayat → Log Notifikasi; Pegawai Login → Dashboard Mini (KGB/KP nextDue + CreditProgressBar + ForecastBadge). Import: upload → preview OK/gagal → confirm. Konfirmasi naik: DueTable → Dialog. Full di [[DESIGN]].

**System:** Tailwind + shadcn, palette slate + biru #2563EB, Inter, radius 0.5rem, light only v1. Components: Table (TanStack), Badge, Progress, ForecastBadge, DueCard/Table, ImportDialog, HistoryTable + 2 Recharts (Bar KGB/bulan, Donut KP/jenis). Responsive desktop-first (sidebar drawer di <768), a11y WCAG AA, i18n Indonesia.

## 6. Data Model (summary)
**Core tables:** `pangkat` (kode, threshold_next per jenjang), `pegawai` (nip, email, pangkat_id, jenis, tmt_kgb, tmt_kp, kredit decimal 5,1, status), `promotion_history` (pegawai, jenis KGB/KP, dari/ke pangkat, tmt, kredit), `notification_log` (pegawai, type, due_date, channel, status, unique idempoten), `user` (email, role admin/pegawai/viewer, pegawai_id opsional). ER: pangkat 1—N pegawai 1—N history & notif, pegawai 1—1 user. Constraints: UNIQUE nip/email/kode, CHECK kredit>=0, FK RESTRICT/CASCADE/SET NULL, indexes di tmt_kgb/tmt_kp/jenis/status. Growth <10k rows, soft-delete via status nonaktif. Full di [[SCHEMA]].

## 7. Rules (summary)
**Baseline:** TS strict + ESLint next/core-web-vitals + Prettier, Husky lint-staged, zod env. Single repo, import hanya dari `lib/`/`components/`. Naming: file kebab, component Pascal, DB snake via `@map`. Larang `any`, `console.log` prod, circular import.

**Testing/CI:** Unit wajib `lib/schedule` & `lib/credit` (70% lib), integration cron & import; gate `lint+typecheck+test+prisma validate` blokir merge ke `main` (protected, 1 approval).

**Human:** PR-based, secret di VPS `.env` 600, deploy manual `git pull && compose up`.

**AI-agent (keras):** FORBIDDEN tanpa approval: `git push --force`, `rm -rf`, `prisma migrate reset`, `DROP/DELETE tanpa WHERE`, edit `.env`/infra, push ke `main` atau merge sendiri. ALLOWED di `ai/*`: edit app/components/lib/prisma, run lint/typecheck/test, buka PR ke `dev`. Full di [[RULES]].

## 9. Decision Log
| # | Decision | Why (alternatives rejected) | Stage |
|---|----------|------------------------------|-------|
| D-PRD-01 | Threshold per pangkat di master `pangkat` (bukan flat 100) | Tiap jenjang beda (3B→3C 100, 3C→3D 150) — flat ditolak tidak akurat | PRD |
| D-PRD-02 | Kredit reset 0 saat naik (bukan carryover sisa) | Sesuai contoh Q10 (145+12.5→157.5≥150 → reset 0); carryover ditolak demi konsistensi instansi | PRD |
| D-PRD-03 | Forecast H-60 untuk fungsional = prediksi 1 Jan vs threshold | Kalau cek kredit real-time baru, telat 2 bulan; forecast 1 Nov untuk 1 Jan adalah inti Q10 | PRD |
| D-PRD-04 | Webhook di samping email (bukan ganti) | Extension point untuk WA/n8n v2 tanpa ubah core; email tetap primary | PRD |
| D-PRD-05 | Riwayat kenaikan masuk MVP | Diminta eksplisit Q6 — audit tidak bisa tunda v2 | PRD |
| D-ARCH-01 | Monolith Next.js (bukan microservice) | 100 pegawai, 1 VPS, tim kecil — deploy simpel; microservice overkill, akan extract worker jika >5k | ARCH |
| D-ARCH-02 | Postgres + Prisma (bukan MySQL) | `timestamptz` + interval + decimal presisi untuk +2y/+4y & 12.5; Prisma type-safe | ARCH |
| D-ARCH-03 | Cron systemd timer → HTTP (bukan Vercel/pg_cron) | VPS on-prem, visible di systemctl, idempoten via DB; node-cron hanya fallback dev | ARCH |
| D-ARCH-04 | Async in-process Promise.allSettled tanpa Redis | Volume <25 email/hari, hindari infra Redis; retry 1x cukup untuk 95% SLA | ARCH |
| D-ARCH-05 | Webhook HMAC sebagai future WA path | v2 WA tinggal pasang gateway verify HMAC tanpa deploy ulang | ARCH |
| D-DES-01 | Light only v1, 2 chart Recharts | Cepat ship; dark deferred; 2 chart cukup untuk insight bulanan tanpa overload | DESIGN |
| D-DES-02 | Desktop-first responsive | Admin di kantor desktop, pegawai mobile cukup stack cards; tidak mobile-first | DESIGN |
| D-SCH-01 | `pangkat` tabel sendiri + `pegawai.kredit` kolum (bukan tabel kredit terpisah) | Threshold editable admin tanpa deploy; 1 kredit per pegawai simpel untuk 100 orang | SCHEMA |
| D-SCH-02 | Soft-delete via `status=nonaktif` | History/notif FK tetap valid; hard delete ditolak | SCHEMA |
| D-SCH-03 | UNIQUE idempoten di notification_log | Cegah double-kirim saat cron rerun — core reliability | SCHEMA |
| D-RUL-01 | TS strict + ESLint+Prettier + Husky | Cegah miscalculate KGB/KP akibat `any` / silent error | RULES |
| D-RUL-02 | AI FORBIDDEN push --force / migrate reset / DROP | VPS prod single-host, salah reset = hilang history 100 pegawai | RULES |
